# 7. الترجمة و RTL

## لماذا لم نستخدم مكتبة i18n؟

مكتبة مثل i18next تحتاج إعدادًا وملف تهيئة ومفاهيم إضافية. احتياجنا بسيط: قاموسان ودالة ترجمة. كتبنا 80 سطرًا نفهمها كلها بدل تعلّم مكتبة كاملة.

## الملفات

- `src/locales/ar.js` — كل النصوص العربية.
- `src/locales/en.js` — كل النصوص الإنجليزية.
- `src/context/I18nContext.jsx` — المنطق.

الملفان لهما **نفس المفاتيح بالضبط**. أي مفتاح ناقص يظهر بالإنجليزية تلقائيًا بدل أن يكسر الصفحة.

## شكل القاموس

```js
const ar = {
  nav: { home: "الرئيسية", books: "الكتب" },
  common: { loading: "جارٍ التحميل..." },
};
```

## استخدام الترجمة

```jsx
const { t } = useI18n();
<h1>{t("nav.home")}</h1>
```

`t` تبحث عن المسار داخل القاموس، وإن لم تجده تُعيد النص الإنجليزي، وإن لم تجده أيضًا تُعيد المفتاح نفسه. هذا يجعل الأخطاء مرئية بدل أن تكون صامتة.

## القيم المتغيّرة داخل النص

بعض النصوص تحتوي بيانات يدخلها المستخدم، مثل عنوان الكتاب:

```js
coverOf: "غلاف كتاب {title}"
```

```jsx
t("common.coverOf", { title: book.title })
```

## تبديل الاتجاه

عند تغيير اللغة يحدث التالي في `I18nContext`:

```js
root.setAttribute("lang", lang);
root.setAttribute("dir", lang === "ar" ? "rtl" : "ltr");
```

وعليه:

- ينقلب ترتيب العناصر تلقائيًا.
- يتبدّل الخط إلى Cairo.
- تنعكس أيقونات الاتجاه.

## قاعدة مهمة

> لا نص مكتوب مباشرة داخل JSX. كل نص للمستخدم يمرّ من `t`.

الاستثناء الوحيد: أسماء الكتب والمؤلفين القادمة من API، فهي بيانات وليست واجهة.
