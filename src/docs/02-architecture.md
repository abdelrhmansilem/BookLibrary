# 2. المعمارية والهيكل

## الطبقات

الكود مقسوم إلى أربع طبقات واضحة، وكل طبقة تعرف فقط الطبقة التي تحتها:

```
الصفحات (pages)      ← تجيب البيانات وتختار ماذا تُظهر
      ↓
المكوّنات (components) ← تعرض props فقط، لا تعرف من أين جاءت
      ↓
الحالة المشتركة (context) ← اللغة، الثيم، المفضلة
      ↓
الخدمات (services)    ← الشبكة، وتُعيد بيانات منظّمة
```

## القاعدة الذهبية

> **الصفحة تجلب، والمكوّن يعرض.**

مكوّن مثل `BookCard` لا يعرف شيئًا عن Open Library. يستقبل كائن كتاب:

```jsx
<BookCard book={book} />
```

وهذا يجعل المكوّن قابلًا للاختبار ولإعادة الاستخدام، وأسهل في الشرح.

## شجرة المكوّنات وقت التشغيل

```
main.jsx
  BrowserRouter
    I18nProvider
      ThemeProvider
        FavouritesProvider
          App
            Layout
              Navbar
              main > Outlet > الصفحة الحالية
              Footer
```

كل مزوّد (Provider) مسؤول عن قيمة واحدة. هذا الفصل يعني أن تغيير الثيم لا يعيد رسم قائمة الكتب، وتغيير اللغة لا يمسّ المفضلة.

## لماذا هذا الهيكل؟

- ملفات صغيرة يسهل قراءتها في المناقشة.
- مسؤولية واحدة لكل ملف: من السهل الإشارة إلى السطر المسؤول عن سلوك معيّن.
- الاعتماد في اتجاه واحد: لا يستورد `services` أي مكوّن، ولا تستورد `components` أي خدمة.

## دورة حياة طلب بيانات (مثال صفحة الكتاب)

1. المستخدم يفتح `/books/OL45804W`.
2. `BookDetails` يقرأ `id` من `useParams`.
3. `useFetch` ينفّذ `getBook(id)` ويضبط `loading = true`.
4. `openLibrary.js` ينادي `https://openlibrary.org/works/OL45804W.json`.
5. الاستجابة تُمرَّر على `normalizeBook` فتصبح كائنًا موحّدًا.
6. الصفحة تعرض الغلاف والمعلومات، أو رسالة خطأ إن فشل الطلب.
